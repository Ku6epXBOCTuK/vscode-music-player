# Пошаговый план разработки

По каждому шагу: **что делать** → **когда готово** (definition of done) →
**ручная проверка**.

## Этап 0: Каркас проекта (~0.5 дня)

1. **Что**: `cargo new backend`, добавить зависимости из §4.2 PDR (axum, tokio,
   tower-http, serde, symphonia, rubato, flacenc, reqwest). `GET /api/health`
   возвращает `{ "status": "ok" }`. **Готово**: `cargo run` стартует,
   `curl http://127.0.0.1:3000/api/health` отвечает 200. **Проверить вручную**:
   открыть `http://127.0.0.1:3000/api/health` в браузере.
2. **Что**: загрузка `config.json` рядом с бинарём; при отсутствии — создать
   дефолтный; при занятом порту — понятная ошибка. **Готово**: файл появляется
   при первом запуске; повторный запуск читает его; второй инстанс падает с
   сообщением про порт. **Проверить вручную**: удалить config.json → запустить →
   файл создан; запустить два бинаря → второй ругается.

## Этап 1: Стриминговое ядро (~3–4 дня)

1. **Что**: пайплайн «один MP3-файл по кругу» — symphonia decode → PCM.
   **Готово**: декодер выдает сэмплы без паник на тестовом файле; логируется
   длительность и sample rate. **Проверить вручную**: подсунуть MP3, FLAC, WAV —
   все декодируются.
2. **Что**: ресемплинг rubato к 48 кГц stereo + применение gain из конфига.
   **Готово**: на выходе всегда 48k/2ch/f32 независимо от входа (лог
   параметров). **Проверить вручную**: файл 44.1kHz mono → выход 48k stereo.
3. **Что**: FLAC-кодирование flacenc + `GET /stream` (broadcast →
   `Body::from_stream`, заголовки из §3.3 PDR, FLAC-заголовок первым чанком
   новому клиенту). **Готово**: `curl http://127.0.0.1:3000/stream -o out.flac`
   — файл растет, VLC проигрывает `out.flac` как звук. **Проверить вручную**:
   VLC → открыть сетевой поток `http://127.0.0.1:3000/stream` → играет музыка.
4. **Что**: критический эксперимент — OBS Media Source на `/stream`. **Готово**:
   OBS проигрывает поток; при отключении/переподключении восстанавливается.
   **Проверить вручную**: добавить Media Source в OBS → звук есть; перезапустить
   бэкенд → OBS переподключается. **Если OBS не ест FLAC — fallback на PCM/WAV и
   правка §3.3/§6 PDR.**
5. **Что**: бесшовный переход между треками (2–3 разных файла подряд в один
   FLAC-стрим). **Готово**: VLC/OBS играют непрерывно, без щелчков и обрывов на
   границе. **Проверить вручную**: слушать переход трек→трек в OBS.

## Этап 2: Плейлисты и API (~3–4 дня)

1. **Что**: сканер локальной папки (рекурсивно, MP3/FLAC/WAV/AAC), очередь
   треков, состояние плеера в памяти. **Готово**: плейлист из конфига
   проигрывается по порядку, по кругу. **Проверить вручную**: папка из 5 файлов
   → слышны все по очереди.
2. **Что**: `/api/control`, `/api/volume`, `/api/now_playing` (см. §3 PDR).
   **Готово**: команды меняют состояние ≤ 200 мс; громкость слышно в потоке;
   `now_playing` отдает текущий трек. **Проверить вручную**:
   `curl -X POST .../api/control -d '{"action":"pause"}'` → тишина; volume 0.2
   vs 1.0 → разница на слух.
3. **Что**: интернет-радио как источник (reqwest → symphonia → общий пайплайн),
   тишина при обрыве станции. **Готово**: 2 тестовые станции играют; при
   отключении интернета стрим не рвется (тишина), при возврате — звук.
   **Проверить вручную**: переключить плейлист на радио → играет; выдернуть сеть
   на 10 сек → поток в OBS не умирает.
4. **Что**: `GET /` — SPA (один HTML через `include_str!`): список плейлистов,
   добавление папки/радио, кнопки play/pause/next. **Готово**:
   `GET/POST /api/playlists` работают; изменения сохраняются в config.json и
   переживают рестарт. **Проверить вручную**: открыть `http://127.0.0.1:3000` в
   браузере → добавить папку → рестарт → папка на месте.

## Этап 3: Расширение VS Code (~1–2 дня)

1. **Что**: `yo code` (TypeScript + esbuild), команды и StatusBar-кнопки
   `[▶/⏸] [⏭] [🔉]`. **Готово**: кнопки видны в футере, нажатия шлют POST на
   бэкенд (видно в логах бэкенда). **Проверить вручную**: F5 (Extension
   Development Host) → клик Play → OBS играет.
2. **Что**: отображение текущего трека — опрос `/api/now_playing` раз в 3 сек,
   текст в StatusBar. **Готово**: название трека обновляется при смене; при
   недоступном бэкенде — иконка «плеер выключен» без спама ошибками. **Проверить
   вручную**: переключить трек → статус-бар обновился; убить бэкенд → расширение
   не падает.
3. **Что**: автозапуск бэкенда через `child_process`, если `/api/health` не
   отвечает; бэкенд не убивается при закрытии VS Code. **Готово**: холодный
   старт — музыка доступна без ручного запуска; закрытие VS Code не глушит звук.
   **Проверить вручную**: убить бэкенд, открыть VS Code → `/stream` работает;
   закрыть VS Code → `/stream` работает.

## Этап 4: Трей и полировка (~2 дня)

1. **Что**: иконка в трее (`tray-icon`): меню «Открыть настройки» / «Выход»,
   tooltip = текущий трек; `#![windows_subsystem = "windows"]`. **Готово**:
   иконка видна; «Выход» корректно завершает процесс; консольное окно не
   появляется. **Проверить вручную**: запустить бэкенд двойным кликом → нет
   консоли, есть трей; Выход → процесс исчез из диспетчера задач.
2. **Что**: `POST /api/shutdown` + кнопка в SPA. **Готово**: после вызова
   процесс завершается кодом 0, config.json сохранен. **Проверить вручную**:
   кнопка «Выключить» в браузере → бэкенд умер, конфиг на диске.
3. **Что**: soak-тест — 2+ часа непрерывного стрима с переключениями треков и
   плейлистов. **Готово**: нет рассинхрона, утечек памяти (диспетчер задач),
   обрывов OBS. **Проверить вручную**: оставить играть на вечер, периодически
   переключать плейлисты.

## Итого

~9–12 дней. Критический пункт — этап 1, шаг 4 (OBS + FLAC): если провал,
fallback на WAV и корректировка PDR, дальнейшие этапы не блокируются.
