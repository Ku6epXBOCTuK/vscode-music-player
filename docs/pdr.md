# Предварительный проект решения (PDR): Локальный музыкальный плеер

## 1. Введение и цели проекта

Цель проекта — создание легковесного музыкального плеера, интегрированного в
рабочее пространство разработчика, с возможностью трансляции звука в OBS Studio
(или любой другой плеер/стриминг-софт).

Ключевые требования:

- **Интеграция с VS Code**: минималистичное управление через кнопки в
  статус-баре (Play/Pause, громкость, переключение плейлистов).
- **Автономная панель настроек**: web-интерфейс в браузере для добавления
  локальных папок с музыкой и ссылок на интернет-радиостанции.
- **Трансляция (стриминг)**: вещание аудио-потока по HTTP (локальная ссылка) для
  подключения в OBS Studio как Media Source.
- **Технологический стек**: бэкенд на Rust, клиент-расширение на TypeScript.

## 2. Архитектура системы

Система разделена на два независимых компонента, взаимодействующих по HTTP (REST
API / Chunked Stream).

```txt
┌──────────────────────────┐
│ VS Code Extension        │─── HTTP POST (команды) ───┐
│ (интерфейс управления)   │                           │
└──────────────────────────┘                           ▼
┌──────────────────────────┐                      ┌────────────────────┐        ┌─────────────┐
│ Браузер                  │─ HTTP (HTML/REST) ─► │ Rust Бэкенд        │──────► │ OBS Studio  │
│ (панель настроек)        │                      │ (axum)             │ HTTP   │ (Media      │
└──────────────────────────┘                      │  └─ Аудио-движок   │ Stream │  Source)    │
                                                  └────────────────────┘        └─────────────┘
```

### 2.1. Компоненты системы

#### **1. VS Code Extension (клиент управления)**

- Регистрирует команды управления в редакторе.
- Создает иконки `StatusBarItem` в футере.
- Отправляет HTTP POST-запросы на бэкенд при нажатии на кнопки.

#### **2. Rust Backend (сервер и аудио-движок)**

- **HTTP-сервер (axum)**: обрабатывает команды управления, отдает веб-страницу
  настроек, организует вещание потока.
- **Диспетчер плейлистов**: сканирует локальные директории (MP3/FLAC),
  подключается к интернет-радио.
- **Аудио-конвейер**: единый пайплайн «любой источник → PCM 48 кГц stereo → FLAC
  → broadcast» (см. §6).

## 3. Спецификация API

Бэкенд поднимает HTTP-сервер на `http://localhost:3000`.

### 3.1. Управление (VS Code и браузер)

| Метод | Маршрут         | Тело (JSON)                                                                             |
| ----- | --------------- | --------------------------------------------------------------------------------------- |
| POST  | `/api/control`  | `{ "action": "play" \| "pause" \| "stop" \| "next_playlist" \| "prev_playlist" }`       |
| POST  | `/api/volume`   | `{ "volume": 0.5 }` — значение от 0.0 до 1.0                                            |
| POST  | `/api/shutdown` | Пустое тело — корректная остановка бэкенда (кнопка в панели настроек / команда VS Code) |

### 3.2. Настройки и состояние (браузер, VS Code)

| Метод | Маршрут            | Описание                                                                 |
| ----- | ------------------ | ------------------------------------------------------------------------ |
| GET   | `/`                | SPA-страница (HTML/JS) управления плейлистами                            |
| GET   | `/api/playlists`   | Список текущих плейлистов и источников                                   |
| POST  | `/api/playlists`   | Добавить новую папку или URL радио                                       |
| GET   | `/api/now_playing` | Текущий трек/станция + состояние (play/pause, громкость) — для StatusBar |
| GET   | `/api/health`      | Health-check: `{ "status": "ok", "version": "..." }`                     |

### 3.3. Вывод звука (OBS)

- **GET `/stream`** — бесконечный FLAC-поток (PCM 48 кГц stereo внутри
  FLAC-контейнера).
- Заголовки ответа:
  - `Content-Type: audio/flac`
  - `Cache-Control: no-cache`
  - `Transfer-Encoding: chunked`
  - `Connection: keep-alive`

## 4. Стек технологий

### 4.1. VS Code Extension

- **Язык**: TypeScript
- **Сборщик**: esbuild (встроен в шаблон VS Code)
- **API**: `vscode.window.createStatusBarItem` для кнопок, встроенный `fetch`
  для команд

### 4.2. Rust Backend

| Назначение              | Библиотека               | Примечание                                                                   |
| ----------------------- | ------------------------ | ---------------------------------------------------------------------------- |
| Асинхронная среда       | `tokio` (multi-thread)   |                                                                              |
| Веб-фреймворк + CORS    | `axum` + `tower-http`    |                                                                              |
| Сериализация            | `serde` + `serde_json`   |                                                                              |
| Декодирование аудио     | `symphonia`              | MP3, FLAC, WAV, AAC; чистый Rust; поддерживает потоковое декодирование радио |
| Ресемплинг              | `rubato`                 | Приведение всего к 48 кГц stereo; чистый Rust                                |
| FLAC-кодирование        | `flacenc`                | Единый выходной формат; чистый Rust, без C-зависимостей                      |
| HTTP-клиент (радио)     | `reqwest`                | Только MP3/AAC-станции                                                       |
| Бродкаст потока         | `tokio::sync::broadcast` |                                                                              |
| Иконка в системном трее | `tray-icon`              | Меню: «Открыть настройки», «Выход»; текущий трек в tooltip                   |

Весь аудио-стек — чистый Rust, без ffmpeg и C-библиотек.

## 5. Хранение данных

Конфигурация хранится в `config.json` рядом с исполняемым файлом бэкенда
(portable-режим — вся установка в одной папке):

```json
{
  "current_playlist_index": 0,
  "volume": 0.8,
  "port": 3000,
  "playlists": [
    {
      "name": "Локальный Lo-Fi",
      "type": "local_folder",
      "path": "C:/Users/user/Music/LoFi"
    },
    {
      "name": "Synthwave Radio",
      "type": "network_radio",
      "path": "https://example.com/stream"
    }
  ]
}
```

Пути в конфиге платформозависимы — нормализация при загрузке (прямые слэши
внутри, конвертация при чтении).

## 6. Аудио-движок (Rust)

Единый конвейер — **всё приводится к PCM 48 кГц stereo и кодируется во FLAC**.
Это решает сразу три проблемы: смешанные форматы в плейлисте, регулировку
громкости и бесшовные границы треков.

```txt
[MP3/FLAC/WAV/AAC файл] ──symphonia──┐
                                     ├─► PCM ──► [rubato: →48k stereo] ──► [gain: volume]
[Интернет-радио MP3/AAC] ──symphonia─┘                                          │
                                          [flacenc: FLAC encode] ◄──────────────┘
                                                    │
                                          [tokio::sync::broadcast]
                                                    │
                                          [/stream → OBS, браузер, ...]
```

1. **Декодирование**: `symphonia` читает локальный файл (`std::fs::File`) или
   поток радио (`reqwest`-стрим). На выходе — сырые PCM-сэмплы.
2. **Нормализация**: `rubato` ресемплирует всё к 48 000 Гц, 2 канала, f32.
   Гарантирует, что параметры потока никогда не меняются.
3. **Громкость**: умножение PCM-сэмплов на коэффициент из `config.volume`.
   Работает одинаково для файлов и радио.
4. **Кодирование**: `flacenc` пакует PCM во FLAC-фреймы непрерывным потоком
   (один FLAC-стрим на всю сессию вещания — границы треков неразличимы для
   декодера).
5. **Раздача**: фреймы уходят в `tokio::sync::broadcast`-канал; `/stream` отдает
   `Body::from_stream()` на `Receiver` канала. Подключившийся клиент получает
   FLAC-заголовок заново (заголовок кэшируется и шлется первым чанком каждому
   новому подписчику).

Битрейт итогового потока ~0.7–1 Мбит/с — для localhost несущественно. CPU:
FLAC-кодирование дешевое, узкое место — ресемплинг (приемлемо на одном ядре).

## 7. Дорожная карта

### Этап 1: Стриминговое ядро (Rust)

- Инициализация проекта (`cargo new`).
- Пайплайн «один MP3-файл по кругу → PCM → FLAC → `/stream`».
- **Критический эксперимент**: подключить `http://localhost:3000/stream` в OBS
  Studio как Media Source и проверить, что OBS декодирует FLAC-over-HTTP. Если
  нет — fallback: PCM/WAV-стрим (`Content-Type: audio/wav`) или переезд на
  Icecast-совместимый протокол.

### Этап 2: Плейлисты и API управления (Rust)

- Парсинг папок, подключение радио (MP3/AAC-станции).
- Обработчики `/api/control`, `/api/volume`, `/api/now_playing`, `/api/health`.
- HTML-страница настроек на `GET /`.

### Этап 3: Расширение VS Code (TypeScript)

- Генерация расширения через `yo code`.
- Кнопки в StatusBar: `[▶/⏸] [⏭] [🔉]` + отображение текущего трека (опрос
  `/api/now_playing`).
- Интеграция `fetch`-запросов к бэкенду.

### Этап 4: Полировка и тестирование

- Иконка в трее (меню + tooltip с треком), обработчик `/api/shutdown`, сборка
  без консольного окна.
- Автозапуск Rust-бэкенда при активации расширения (см. §8, решение по
  жизненному циклу).
- Тесты стабильности: переключение треков, длинные сессии, переподключение OBS.

## 8. Принятые решения и оценка сложности

**Решения по бывшим открытым вопросам:**

1. **Формат потока** — FLAC через `flacenc`, чистый Rust (см. §6). Fallback при
   проблемах с OBS — PCM/WAV.
2. **Громкость** — на PCM до кодирования, работает для файлов и радио.
3. **Границы треков** — один непрерывный FLAC-стрим, проблема снята
   нормализацией к 48k stereo.
4. **Радио** — декодируется в тот же пайплайн; поддерживаем только
   MP3/AAC-станции, экзотика вне скоупа.
5. **Метаданные** — эндпоинт `/api/now_playing` (poll из VS Code раз в 2–5 сек).
   ICY-metadata в поток не внедряем.
6. **Лаг broadcast-клиента** — при `Lagged` клиент отключается; OBS настроен на
   автоматический reconnect (галка в Media Source). Проверяется на этапе 1.
7. **Жизненный цикл бэкенда** — расширение VS Code стартует бэкенд через
   `child_process` при активации, если `/api/health` не отвечает; не убивает при
   закрытии (бэкенд — независимый сервис). Занятый порт → бэкенд падает с
   понятной ошибкой, расширение показывает сообщение.
8. **Конфиг** — `config.json` рядом с бинарём бэкенда, portable-режим (см. §5).
9. **Безопасность** — осознанно без токена: bind только на `127.0.0.1`, API
   недоступен извне. Зафиксировано как допустимый риск локального инструмента.
10. **SPA** — один HTML-файл с vanilla JS, встроен в бинарь через
    `include_str!`. Без сборщика.
11. **Закрытие приложения** — иконка в системном трее (`tray-icon`) с меню
    «Открыть настройки» / «Выход», tooltip показывает текущий трек. Запасной
    канал — `POST /api/shutdown`. На Windows бэкенд собирается с
    `#![windows_subsystem = "windows"]` (без консольного окна), tray-icon держит
    message loop.

**Оценка сложности:**

| Компонент                                            | Сложность      | Оценка  |
| ---------------------------------------------------- | -------------- | ------- |
| HTTP API (5 эндпоинтов)                              | Низкая         | 1–2 дня |
| Панель настроек (SPA)                                | Низкая         | 1 день  |
| VS Code Extension                                    | Низкая–средняя | 1–2 дня |
| Аудио-пайплайн (decode→resample→gain→FLAC→broadcast) | Средняя        | 3–4 дня |
| Поддержка радио (MP3/AAC)                            | Средняя        | 1–2 дня |
| Автозапуск из VS Code                                | Низкая         | 0.5 дня |

**Итого MVP: ~8–10 дней.** Главный оставшийся риск — совместимость FLAC-потока с
OBS (проверяется в первый день этапа 1).

## 9. Риски и решения

| Проблема                                       | Решение                                                                      |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| OBS не декодирует FLAC-over-HTTP               | Fallback на PCM/WAV-стрим; проверка — первый эксперимент этапа 1             |
| OBS кэширует поток → задержка при переключении | `Cache-Control: no-cache`; при необходимости — разрыв соединения и reconnect |
| CORS блокирует запросы из VS Code              | `tower_http::cors::CorsLayer::permissive()`                                  |
| Медленный клиент отстает от broadcast          | Отключение при `Lagged` + reconnect в OBS                                    |
| Радио-станция отваливается/лагает              | Тишина (нули PCM) в поток до восстановления; стрим не рвется                 |
